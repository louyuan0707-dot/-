# 剧梦逐处内联资产引用

仅用于剧梦节点派生提示词。正式分镜仍按原定七栏保存原文；内联引用属于派生稿中的富文本资产标签，不得改写「台词」栏的英文旁白或人物对白。

## 先定身份与版本

为每个可见人物记录 `角色身份 ID → 剧情时间／状态 → 已批准形象 ID → 剧梦可选资产名`；场景和独立道具同样记录资产类别、状态和形象 ID。身份 ID 指同一个剧中人物，形象 ID 指此时此镜实际使用的视觉版本。例如男主当前与男主回忆是同一身份的两个版本，男二始终是另一身份。不能用相似文件名、相邻候选、主形象默认项或角色称谓推断版本。缺少已批准的回忆版时标记待补并停在提交前，不能拿男二或男主现时版临时代替。

逐镜先列画面中实际可见的资产和状态，再记录每处引用的位置：`集／组／镜号｜栏位与文本位置｜角色身份 ID｜剧情状态｜应选形象 ID｜实际标签 ID`。同一镜的两个角色要分开登记；一个角色在本组换装、进入回忆或从回忆返回时，逐处核对前后版本及切换点。仅声音、仅被台词提及、画面外人物不因名字出现而贴人物图片标签。

## 像界面资产标签那样引用

一键引用关系保存并核实后，在**每个镜头正文中实际描述人物、场景、独立道具的位置**插入该版本的真实剧梦资产标签；人物栏、场景栏、情节／画面／动作等视觉描述中的相应提及都要在标签生效后回读。组头对照表、组级卡片或镜头前一行 `本镜引用` 可留作内部核对，但均不能代替正文内联标签。台词里的角色名和英文原句保持纯文本，不能为贴图而改动。

使用平台当前支持的一键引用或 Dreama `prompt assemble` 生成真实标签，选择精确形象名及 ID；不要手写、格式化或篡改平台返回的 span／标签，也不要用模糊子串全局替换普通人物名。不同人物或同一人物不同状态的引用名若相互包含、重名或易被自动替换混淆，先改用该项目中唯一且明确的形象名／受控占位，再逐处引用；不把“男主”“他”“回忆中的人”自动当成某张图。若一键引用误把台词里的名字也变成图片标签，恢复原台词并改用精确的逐处选择方式。平台若不能可靠地为每处插入并读回标签，停止提交，不以纯文字名、顶部卡片或单独资产清单冒充完成。

## 提交前逐处核验

1. 回读**提交框中的最终富文本**，而不是只看原始纯文本或组头卡片。逐处核对标签的类别、显示名、真实形象 ID、相邻句的角色身份和剧情状态；尤其检查回忆、闪回、换装、双人同框及组界。悬停、点击或使用 CLI 返回的可解析数据核对 ID，不能只凭标签颜色和近似名称判断。
2. 对每镜比较 `应有的可见资产提及集合` 与 `最终正文内联标签集合`：数量、顺序、身份、版本、ID 全部相符；不得有漏贴、错贴、重复贴、错误主形象、姓名嵌套或 `请选择`。组级绑定须与正文标签一致，但不作为替代验收。
3. 检查平台字符上限及提示词截断。优先减少组头重复说明和无用的长文件名，保留每处必要标签；不能为了压字数删掉正文引用或把回忆版改成其他角色。再核对人物对白原文、旁白已从生成发声稿移除、时长与模型。提交后若成片角色变错，记录镜号、错误标签 ID 与预览证据，停止自动重生。
