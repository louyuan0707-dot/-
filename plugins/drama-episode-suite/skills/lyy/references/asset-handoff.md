# 资产与引用交接

## 资产清单

从剧本、正式分镜和已批准资产建立同一张可恢复清单。每项记录角色或场景的正式名、别名、类别、剧情状态与适用集组、原始文件路径和哈希、画面依据、选中人脸／服饰参考的链接或可定位信息及其具体用途、批准版本、剧梦素材 ID 与形象 ID。原文只提到或只有声音、没有出镜需求的人物，记录为文字项，不自动生图。服装、体型、年龄阶段不同的同一人物分别关联形象；同一地点换机位不自动新建场景；与场景一体的普通陈设不自动生成独立道具。

## 图片验收和上传

已有资产先看图再决定复用，不能只凭文件名或哈希认定正确。人物分开看身份、脸型／果头、体型、服装和必要视角；多视角同一身份与服装结构必须一致。布局参考只控制排版，服装参考只控制服装，不能把参考中的脸或其他人物带入。按[场景与道具资产制作规则](scene-prop-design.md)检查场景的位置关系、光向、可行动空间、冷暖平衡及无人物／独立道具；道具检查一图一件、结构和剧情用途，且无中文、logo、旗帜、国徽或其他品牌／机构标志。风格按当前剧本确定，不套用其他 Skill 的真人融脸、固定身高、强制叠穿、固定套数或四视图规格。

用户批准的是特定图片版本，不自动批准同角色后续换装或其他候选。上传前按类别和文件名建立稳定批次，遵守当前页面或 CLI 实际限制；上传后按名称与缩略图核对每项，不能依赖异步出现顺序。上传结果未知时先查现有素材，只补确实缺失的项，不重传整批。

## 一键引用与节点引用

上传和保存引用映射是两个不同状态。参考名采用当前项目已确认的正式资产名或唯一别名，不强制从文件名剥去英文；原始文件名、正式名和剧梦形象 ID 必须一一对照。不同图片若会得到同一个引用名，或名称存在包含关系并可能使自动替换串绑，先确定唯一无歧义名称或受控短标记，再保存。不能凭列表相邻项猜图片；不得覆盖项目里已有且指向不同图的同名关系。

配置完一键引用后，重新打开核对持久化的每项名称、类别和图片对应关系，不能把弹窗内暂时配对当作已保存。每个视频节点只绑定本组实际出现且已批准的资产；组级绑定与顶部对照表只供核对。实际生成用的派生提示词须按[逐处内联资产引用](inline-references.md)在镜头正文的每处可见人物、场景和独立道具提及处插入真实资产标签，逐处回读形象 ID 与剧情状态；镜头前的短名和 ID 也不能代替正文标签。若平台自动替换文本，检查无「请选择」、错人物、错回忆版、错服装、姓名嵌套、重复词或缺失引用。核验失败时停在提交前。
