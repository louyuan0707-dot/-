# 项目事实与资产需求基线

## 建基线

为本剧保留唯一项目身份、当前剧本版本、分集范围和视觉体系版本；记录源文件哈希、已读集场、未读范围及各条事实的集／场／原文位置。只在已覆盖范围内声称资产清单完整。恢复任务时先读基线、变更范围和对应原文；源文件未变则沿用已核实台账，变更时仅使相关事实、资产和分镜失效，不重读或重做无关集组。

分开标记：`剧本明示`、`依据剧情推断的设计`、`用户确认`、`待核冲突`。剧本文字是剧情和台词的依据；用户确认的图片是对应资产版本的依据，不能反过来改写原文。姓名、关系、时代、地点或道具状态出现矛盾时，先查上下文；仍无法确定且影响制作时，记录冲突位置和受影响产物，在依赖该结论的生成前处理。不要擅自修剧本，也不把普通资产提取变成全剧审校。

## 三类独立需求表

- **人物**：统一身份、已证实别名、角色重要度、首次及重复出镜、现实／回忆／照片／屏幕等呈现方式、与他人关系；将固定年龄或身份版本、临时服装和当场情绪分开。仅提及、纯声音、背景群体分别标记。按画面重复使用与一致性需求排资产优先级，不能仅按戏份或称谓判断。未证实同一人的别名不合并。
- **场景**：统一空间身份、别名、室内外、独立房间或活动区域、首次及重复使用、现实／回忆等属性、昼夜天气版本。依据实际画面空间决定是否需要独立资产；对白中提到但未出现的地点不列成画面。不同机位、人物进出不拆新场景；同楼不同房间、车内外或画中画空间可按实际画面分别记录。优先级看复用和连续性。场景图只作空置建筑／空间，不预放人物或可移动道具；剧情物件留给镜头描述或合格的单件道具资产。
- **道具**：记录剧情用途、持有人、首次和再次出现、状态变化、原文要求的可读信息，以及每集实际出现的不同分镜数。某集仅一个分镜出现的道具不为该集单独生图，记为镜头画面细节；跨集反复出现且有连续性需求时再评估共用资产。需要独立道具图时一图一件，不能混合多个物件。

每项资产需求至少指明 `正式名｜类别｜视觉版本／状态｜所需集组｜原文位置｜画面必要性｜优先级｜现有批准图／待制作｜视觉体系版本`。名称不确定时保持待核，不虚构角色名或场景名。

## 交接检查

提取表通过后，才为待制作项写相应类型的提示词。人物提示词依据身份与当前版本区分脸／果头、体型、服装、配饰；参考图逐张注明只用于脸、服装、布局、风格还是局部修改，避免带入参考中的其他身份。同剧角色应可辨认，跨服装和视角保持同一身份。场景提示词写足空间结构、可行动区域、1—3 个固定建筑锚点、材质、时间和光源；执行[场景与道具资产制作规则](scene-prop-design.md)，不把参考街景的具体物件带进本剧。不同视觉体系的固定尾词、真人面孔和 3D 术语不得串用；水果人按本剧批准的拟人化果人基准处理。

逐阶段保存 `输入版本｜覆盖范围｜产物路径／ID｜检查结论｜未决问题｜受影响下游`。用户要求局部重做时，只重做被变更事实或失败检查依赖的资产、分镜、节点；但已提交的剧梦任务不能悄悄覆盖，先核对远端状态和已花积分。
