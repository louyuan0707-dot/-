# 剪映草稿交付

用户要求直接交付可编辑草稿时，预览与必要的内容检查完成后即可生成，不再增加一次笼统批准。用户正在编辑剪映时，在独立工作目录准备，不覆盖当前草稿。

1. 生成有独立名称和 ID 的新草稿；保存原视频、人物原声、旁白、配乐、额外音效及字幕的各自轨道。用户没有提供配乐时如实说明，不能用空轨道表示已完成。
2. 预览与草稿必须共用最终时间线和素材来源。草稿里的媒体路径逐个检查存在；确认总时长、画布、帧率、音量及字幕段数。备份草稿后再修改应用索引。
3. 写入剪映首页索引前先确认剪映及托盘进程完全退出。应用正在运行时请用户保存并退出；不得强制结束进程或在它仍会覆盖索引时反复写入。可调用 `scripts/register_draft.py --draft-root <活跃草稿根目录> --draft-name <新草稿名>`；它先检查媒体路径、备份原索引，再原子登记。同名草稿避免重复登记。登记后核对草稿 ID、目录、时长及备份一致。
4. 重新打开剪映后，以首页可见且能打开、无缺失媒体为最终验收。若无法可靠操作应用，报告已完成的文件与索引检查，明确“剪映内打开和播放未验证”，请用户打开草稿反馈。不能把 JSON 检查说成应用内验收。

用户指定的剪映库内转场、片尾特效或音效须选用原件；未能在应用中加入或核验的，列为待完成，不能以相似素材冒充。
